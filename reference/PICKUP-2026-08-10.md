## 7 remaining stubs

showdigit, setrgb, setpixel, clearmatrix, devicestate, ircode, whenirreceived.

All need new protocol infrastructure:
- **7-segment** (showdigit): needs segment encoding table + shift register or direct GPIO
- **RGB** (setrgb): needs 3-channel PWM, only 2 PCA modules available
- **LED matrix** (setpixel, clearmatrix): depends on display type
- **IR** (ircode, whenirreceived): NEC/RC5 protocol decode, needs timer interrupt
- **devicestate**: composite readback, needs circuit topology to be meaningful

## What was ruled out

- **WS2812 on 12T**: impossible. 1 cycle = 1085 ns > entire 0-bit window (250-550 ns). Greyed at compile time and in palette. (Verified 2b by ucsim-stc fbc15bf.)
- **I2C ACK in simulation**: bw-board's feedI2C skips the ACK clock (line 60 of i2c-parts.js). Model observes, does not participate. Driver proceeds without ACK check. Asked bw-board if they plan ACK driving; no answer yet.
- **Timer 1 + tethered mode**: incompatible. Ultrasonic driver and 10-live-firmware both claim Timer 1. Warned via BW_COLLISION. Standalone is fine.
- **Instruction-counted timing**: the 1T/12T trap. Every delay must use Timer 0 at FOSC/12 or PCA hardware. The ultrasonic trigger was the concrete failure (4.7 µs on 1T, caught by ucsim-stc). ADC settle loop (adc_read) is pre-existing same-class defect, not yet fixed.
- **RGB via PCA**: only 2 modules (0=servo, 1=motor). A third channel needs software PWM or a different approach.

## vm.test.mjs hang root cause

vm.start() registers a setInterval. If any test assertion fails before vm.quit(), the interval keeps Node alive indefinitely. Fixed with afterEach cleanup + VM tracking set. The 120s test-timeout is a guard, not the fix.
