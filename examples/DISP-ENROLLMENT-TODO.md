# disp-* enrollment — complete (2026-08-23)

The seven `disp-*` display examples are enrolled with hand-authored
`circuit.json` files plus generated, seated per-device benches, and the full
suite is green.

## Why benches were needed at all

Two corpus contracts disagree until an example carries per-device benches:

- `retarget-gallery`: `index.json` `devices` must equal what `retargetPseudocode`
  offers, minus anything ledgered in `transformRefused`.
- `example-corpus-contract`: `devices` must equal authored circuit + **generated
  benches** (`circuit.<device>.json`).

With `devices: ["stc12c5a60s2"]` the first fails; widening it without benches
makes the second fail. Both pass only once `gen-device-benches.mjs batch/seat/
index` has produced and seated real benches.

## The seating overlap: neither the algorithm nor the inputs were wrong

`mcu1 overlaps bb1` across the disp-* benches for `arduino-uno`, `arduino-mega`
and `atmega168p`. The failure list is 18 files, not 5 — every disp-* example ×
those three devices, which is a pattern by DEVICE, not by example.

**Evidence it was not the inputs.** 82 examples carry an authored `circuit.json`
plus generated benches, over the same code path. 76 of them have zero overlaps;
only the six disp-* ones overlap. An input peculiar to disp-* would not spare 76
siblings on the same path.

**Evidence it was not the algorithm.** `layoutFloatingParts` bottom-aligns each
row above the board: `rowBottom = boardTop − gap = 175 − 40 = 135`, and
`y = rowBottom − h/2`. For an Uno (400 × 294 world units) that is **y = −12** —
exactly what the passing benches carry. Called directly with the sidecar
registry loaded it returns `vcc1(58,115) gnd1(134,115) mcu1(392,−12)`, matching
`06-active-low-high` to the unit.

**What was actually wrong.** The committed benches had
`vcc1(80,60) gnd1(156,60) mcu1(232,60)` — a uniform row on a 76-unit pitch,
which is `36 + gap 40`: the pitch of a **supply symbol**. The board had been
sized as a 36 × 40 post instead of a 400 × 294 board, so the packer put it in
the supply row where it necessarily reaches the breadboard. That is the
part-geometry lookup not resolving during the seat run that produced them — the
uninitialised-registry trap `ROADMAP.md` records under "verify the instrument".
`gen-device-benches.mjs` defaults `BW_CUI` to
`~/.claude/jobs/ef2c9a2a/tmp/cui-check`, a path that no longer holds a usable
checkout, which is how such a run gets started by accident.

**Fix:** re-seated all seven with `BW_CUI` pointed at a real bw-circuit-ui
(`8e666ca`) — `seat --reseat --only <id>`, 51 seated, 0 failed. No source change
was warranted on either side; the artefacts were simply generated by a run that
could not see part geometry. Nothing was added to `transformRefused`: every
device here genuinely hosts its example once the board is placed at its true
size.
